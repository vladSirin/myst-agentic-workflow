# Myst evidence additions

Apply these additions within the upstream sections; keep prose brief.

In Summary, include the existing ticket/spec source pointer, or the caller's
justified workflow-skip line. Use the project's tracker and supplied scope. If
the pointer is missing, state that gap and obtain it before treating the body
as complete; do not invent a ticket or claim a workflow skip was approved.

In Evidence, present supplied, usable final Standards and Spec results for the
same source/revision being described. Give the reason for each skipped axis.
A missing, stale, or unverified result is a stated limitation, never GREEN.
Preserve WARNING and BLOCKING results and the actual finding disposition. Link
existing durable review evidence when detail is needed, retaining the source
and revision context. If no usable report exists, include essential unresolved
findings and their known disposition briefly in the body. Keep docs-alignment
results or limitations where relevant. State missing human acceptance explicitly.

Use observed before/after evidence. If a run, screenshot, or before result is
absent, say so; do not turn proposed checks into passed tests. Formatting does
not run a review, resolve a finding, or grant publication approval.

In Merge Danger, retain the source's Door and Blast Radius and describe relevant
remaining risks, including unresolved blockers. Do not hide a risk because a
separate review report exists. Preserve the existing three section headings:
no separate Review Record, mandatory pass-count summary, or new report just to
satisfy this format. Detailed history can stay in the existing evidence.
